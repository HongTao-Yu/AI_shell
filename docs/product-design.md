# AI Shell Assistant 产品设计文档

## 1. 产品概述

### 1.1 产品名称

暂定名称：**AI Shell Assistant**

备选名称：

- ShellMate
- Terminal Copilot
- Linux AI Assistant
- AI Terminal Companion
- Linux 小白助手
- 命令行 Copilot

### 1.2 一句话定位

**一款 Windows 上安装即用的 Linux AI 操作助手，用户用自然语言描述目标，AI 自动拆解为安全、可解释、可逐步确认执行的 Linux 命令，并在执行结果反馈后继续推进任务。**

### 1.3 产品目标

面向 Linux 初学者、开发者、运维人员和算法工程师，解决他们在 Linux 命令行环境下“不知道该敲什么命令”“命令报错不知道原因”“不敢执行高风险命令”“项目跑不起来”“环境排查困难”等问题。

产品希望做到：

1. **极低使用门槛**：Windows 上安装软件，登录账号，添加服务器即可使用。
2. **自然语言驱动**：用户直接说需求，例如“帮我把这个项目跑起来”“帮我查一下磁盘为什么满了”。
3. **逐步命令生成**：AI 每次只生成一条或少量安全可控的命令。
4. **用户接纳后执行**：所有命令默认需要用户确认后再执行。
5. **执行结果反馈闭环**：命令执行后，stdout、stderr、exit code、cwd 等结果反馈给 AI，AI 再决定下一步。
6. **自动报错分析**：命令失败时自动总结原因，并提出下一步排查命令。
7. **兼容现有终端习惯**：优先提供内置 AI SSH 终端，同时逐步适配 Xshell、MobaXterm、SecureCRT、Windows Terminal 等工具。
8. **安全可控**：对删除、覆盖、停服务、sudo、远程脚本、磁盘操作等命令进行风险识别和二次确认。

## 2. 背景与问题

### 2.1 用户痛点

Linux 命令行对小白用户和非运维背景开发者存在较高门槛，常见问题包括：

1. **不会写命令**
   - 不知道怎么查文件、查日志、查端口、查进程。
   - 不知道 tar、grep、find、awk、sed、systemctl、docker 等工具怎么组合。

2. **报错看不懂**
   - Python、Java、CMake、Docker、CUDA、NPU、依赖安装等报错信息复杂。
   - 用户不知道错误原因是环境问题、权限问题、依赖问题还是命令路径问题。

3. **不知道下一步做什么**
   - 当前目录下有 README、requirements.txt、pom.xml、CMakeLists.txt，但用户不知道如何启动项目。
   - 遇到失败后，不知道先查什么、后查什么。

4. **怕误操作**
   - Linux 命令中存在 rm、chmod、chown、dd、mkfs、kill、systemctl stop 等高风险命令。
   - 小白用户不敢执行 AI 生成的命令，缺少信任感。

5. **现有 AI 工具使用成本高**
   - 需要用户复制报错、粘贴给大模型、再复制命令回终端。
   - 缺少对当前目录、环境、历史命令、执行结果的持续上下文理解。

6. **配置复杂**
   - API Key、Base URL、模型名称、代理、证书、Shell Hook、PATH 等配置会劝退小白用户。

### 2.2 市场机会

当前主流 AI 编程工具更偏 IDE、代码补全、代码生成，而 Linux 命令行场景仍存在明显空白。

AI Shell Assistant 的机会在于：

- 不是简单“生成 Linux 命令”，而是“多步命令执行 Agent”。
- 不是单纯“报错解释”，而是“自然语言任务规划 + 用户确认执行 + 结果反馈闭环”。
- 不是要求用户换终端，而是“Windows 安装即用 + 内置终端 + 逐步兼容现有终端”。

## 3. 目标用户

### 3.1 核心用户画像

#### 用户 A：Linux 小白开发者

- 会写代码，但 Linux 基础薄弱。
- 常见任务：部署项目、安装环境、查看日志、启动服务、压缩解压文件。
- 最大痛点：不知道该敲什么命令，报错看不懂。

#### 用户 B：算法/AI 工程师

- 经常使用远程 GPU/NPU 服务器。
- 常见任务：配置 Python 环境、启动训练、排查 CUDA/NPU、Docker、vLLM、PyTorch 报错。
- 最大痛点：环境复杂，报错信息长，排查链路长。

#### 用户 C：后端开发者

- 经常登录服务器查看服务状态、日志、端口、进程。
- 常见任务：查看 Java 服务、排查端口、重启服务、查看磁盘。
- 最大痛点：命令组合复杂，线上操作风险高。

#### 用户 D：初级运维/测试人员

- 需要执行常规服务器维护任务。
- 常见任务：磁盘清理、日志排查、服务状态检查、包安装。
- 最大痛点：担心误删、误停服务、误改权限。

### 3.2 非目标用户

第一阶段不重点服务：

- 资深 Linux 内核工程师。
- 需要完全自动化无人值守运维的企业系统。
- 对安全审计、私有化部署、权限隔离要求极高的大型企业客户。
- 只需要简单命令解释、无需连接服务器的普通用户。

## 4. 产品核心价值

### 4.1 用户价值

1. **把自然语言变成可执行命令**
   - 用户只说目标，不需要知道具体命令。

2. **降低 Linux 使用门槛**
   - AI 解释每条命令为什么执行、风险是什么、预期结果是什么。

3. **减少排障时间**
   - 自动读取命令输出、错误码、当前目录、项目结构，持续推进排查。

4. **增强执行安全感**
   - 所有命令先展示、解释、风险评级，用户接纳后执行。

5. **保留用户控制权**
   - 用户可以接纳、修改、跳过、停止任务。

### 4.2 产品差异化

| 能力 | 普通 ChatGPT | 普通终端 | AI Shell Assistant |
|---|---|---|---|
| 自然语言生成命令 | 支持 | 不支持 | 支持 |
| 自动理解当前服务器上下文 | 不支持 | 不支持 | 支持 |
| 用户确认后执行命令 | 不支持 | 用户手敲 | 支持 |
| 执行结果反馈给 AI | 手动复制 | 不支持 | 自动支持 |
| 多步任务闭环 | 弱 | 不支持 | 支持 |
| 命令风险识别 | 弱 | 不支持 | 强制支持 |
| Windows 安装即用 | 不支持 | 依赖终端 | 支持 |
| 兼容现有终端 | 无 | 本身支持 | 逐步适配 |

## 5. 产品形态

### 5.1 总体形态

产品由三部分组成：

```text
Windows 客户端
  +
远端 Linux Agent
  +
终端适配器
```

#### Windows 客户端

负责：

- 用户登录。
- 模型服务调用。
- 服务器管理。
- 内置 SSH 终端。
- AI 侧边栏。
- 命令建议卡片。
- 用户点击接纳后执行。
- 安全策略展示。
- 任务状态管理。

#### 远端 Linux Agent

负责：

- 采集当前 shell 上下文。
- 执行经用户批准的命令。
- 返回 stdout、stderr、exit code、cwd、执行耗时。
- 支持 bash/zsh/fish hook。
- 支持命令历史和最近错误记录。
- 支持项目结构扫描。

#### 终端适配器

负责：

- 适配 Xshell、MobaXterm、SecureCRT、Windows Terminal 等工具。
- 提供选中文本分析、建议命令粘贴、调用本地 AI 面板等增强体验。
- 第一阶段不作为核心能力，第二阶段逐步补齐。

### 5.2 产品使用模式

#### 模式一：内置 AI SSH 终端

这是第一阶段主推模式。

用户在 Windows 软件中添加服务器后，直接使用内置终端连接 Linux。产品可以完整掌控输入、输出、执行状态和 AI 侧边栏。

优点：

- 实现最可控。
- 用户体验最完整。
- 最适合自然语言任务执行。
- 最容易实现点击接纳后自动执行命令。

#### 模式二：远端 ai 命令模式

用户继续使用 Xshell/MobaXterm 等终端，在 Linux 内输入：

```bash
ai why
ai next
ai cmd "查找最大的 10 个文件"
ai task "帮我把这个项目跑起来"
```

优点：

- 兼容性强。
- 不强迫用户换终端。
- 实现成本适中。

#### 模式三：现有终端适配模式

通过 Xshell/MobaXterm/SecureCRT/Windows Terminal 适配器增强现有终端体验，例如：

- 选中报错文本后右键分析。
- AI 建议命令一键粘贴到终端。
- 本地侧边栏显示命令建议。
- 通过 `ai-ssh.exe` 包装 SSH 连接。

## 6. 核心功能设计

## 6.1 自然语言任务执行

### 功能描述

用户输入自然语言目标，AI 自动拆解成多步命令。每一步都需要展示命令、原因、风险、预期结果，用户点击接纳后执行。

### 示例

用户输入：

```text
帮我把这个 Python 项目跑起来
```

AI 生成第一步：

```bash
ls -la
```

展示：

```text
步骤 1：查看当前目录结构

命令：
ls -la

为什么执行：
先确认当前目录是否包含 README、requirements.txt、main.py、app.py 等项目入口文件。

风险等级：低

预期结果：
看到当前目录下的文件和文件夹。

[接纳并执行] [修改命令] [解释命令] [换一个方案] [停止任务]
```

用户点击“接纳并执行”后，系统自动执行命令，并将输出反馈给 AI。AI 再生成下一步。

### 任务闭环

```text
用户自然语言目标
      ↓
AI 生成下一步命令
      ↓
展示命令、原因、风险、预期结果
      ↓
用户接纳
      ↓
执行命令
      ↓
采集执行结果
      ↓
AI 分析结果
      ↓
继续生成下一步
      ↓
任务完成 / 失败 / 需要用户补充信息
```

### 功能要求

1. 默认每次只生成一条命令。
2. 每条命令必须可解释。
3. 每条命令必须有风险等级。
4. 每条命令默认需要用户点击确认。
5. 执行后必须返回结果给 AI。
6. AI 必须基于真实执行结果决定下一步。
7. 用户可以随时停止任务。
8. 用户可以修改 AI 生成的命令后再执行。

## 6.2 报错自动分析

### 功能描述

当命令执行失败时，系统自动识别 exit code 非 0、stderr 输出、异常堆栈或典型错误文本，并给出原因分析和下一步排查建议。

### 示例

用户执行：

```bash
python train.py
```

失败后，AI 展示：

```text
命令执行失败：python train.py
退出码：1

可能原因：
1. 当前环境缺少 torch。
2. 当前 Python 虚拟环境未激活。
3. 项目依赖没有安装。

建议下一步：
python -c "import torch; print(torch.__version__)"

原因：
先确认 torch 是否已安装，以及当前 Python 是否能正确导入 torch。

[接纳并执行] [解释] [换一个方案]
```

### 功能要求

1. 记录上一条命令。
2. 记录退出码。
3. 记录 stderr 和 stdout 尾部。
4. 支持错误摘要。
5. 支持下一步命令建议。
6. 支持用户点击执行下一步命令。

## 6.3 命令生成与解释

### 功能描述

用户用自然语言描述单个命令需求，AI 生成可复制、可执行、可解释的 Linux 命令。

### 示例

用户输入：

```text
查找当前目录下最大的 10 个文件
```

AI 输出：

```bash
find . -type f -printf "%s %p\n" | sort -nr | head -10
```

解释：

```text
这个命令会递归查找当前目录下所有文件，按文件大小从大到小排序，并显示最大的 10 个文件。
```

按钮：

```text
[接纳并执行] [复制] [解释细节] [换一种写法]
```

## 6.4 下一步建议

### 功能描述

AI 根据当前目录、最近命令、最近输出、项目文件、错误信息，推荐下一步操作。

### 示例

用户当前目录包含：

```text
README.md
requirements.txt
app.py
```

AI 推荐：

```bash
cat README.md
```

原因：

```text
当前目录看起来是一个 Python 项目，先读取 README 中的启动说明，避免盲目运行入口文件。
```

## 6.7 安全命令识别

### 功能描述

所有 AI 生成的命令在执行前必须经过安全策略模块检查。

### 风险等级

| 等级 | 示例 | 策略 |
|---|---|---|
| 低风险 | `ls`, `pwd`, `cat README.md`, `which python` | 可直接确认执行 |
| 中风险 | `pip install`, `apt install`, `docker pull` | 明确提示影响 |
| 高风险 | `rm`, `chmod -R`, `chown -R`, `kill`, `systemctl stop` | 二次确认 |
| 危险 | `rm -rf /`, `mkfs`, `dd`, `fdisk` | 默认禁止 |
| 敏感 | 读取 token、密钥、密码文件 | 默认禁止或脱敏 |

### 高风险命令示例

```bash
rm -rf build
```

展示：

```text
该命令会删除 build 目录。

通常 build 是构建产物目录，可以删除后重新构建。
但如果该目录包含重要文件，删除后可能无法恢复。

请输入“确认删除”后继续。
```

### 危险命令示例

```bash
rm -rf /
```

展示：

```text
该命令极其危险，可能删除整个系统文件。
已被安全策略拦截，无法执行。
```

## 6.8 文件修改与氛围编程

### 功能描述

在高级版本中，AI 可以根据任务需要生成文件修改方案，但必须先展示 diff，用户确认后再应用。

### 示例

用户输入：

```text
帮我修复这个 Python 项目的启动报错
```

AI 分析后生成：

```diff
- import yaml
+ import ruamel.yaml as yaml
```

展示：

```text
AI 建议修改文件：config_loader.py

修改原因：
当前代码使用 yaml.load 但环境中缺少 PyYAML。项目 requirements 中已有 ruamel.yaml，因此建议改用现有依赖。

[应用修改] [拒绝] [查看完整文件] [换一个方案]
```

### 要求

1. 修改前必须展示 diff。
2. 用户确认后才能写文件。
3. 应用后自动运行测试或启动命令验证。
4. 失败后继续分析。

## 8.3 任务状态机

```text
INIT_TASK
    ↓
COLLECT_CONTEXT
    ↓
PLAN_NEXT_STEP
    ↓
SAFETY_CHECK
    ↓
WAIT_USER_APPROVAL
    ↓
EXECUTE_COMMAND
    ↓
OBSERVE_RESULT
    ↓
ANALYZE_RESULT
    ↓
DONE / PLAN_NEXT_STEP / NEED_USER_INPUT / FAILED
```

状态说明：

| 状态 | 说明 |
|---|---|
| INIT_TASK | 用户创建自然语言任务 |
| COLLECT_CONTEXT | 采集 cwd、系统、项目结构等上下文 |
| PLAN_NEXT_STEP | AI 生成下一步命令 |
| SAFETY_CHECK | 对命令进行风险判断 |
| WAIT_USER_APPROVAL | 等待用户接纳、修改或拒绝 |
| EXECUTE_COMMAND | 执行命令 |
| OBSERVE_RESULT | 收集输出和退出码 |
| ANALYZE_RESULT | AI 分析结果 |
| DONE | 任务完成 |
| NEED_USER_INPUT | 需要用户补充信息 |
| FAILED | 任务失败，无法继续 |

## 9. 安全设计

## 9.1 安全原则

1. AI 默认不能直接执行命令。
2. 命令执行必须经过用户确认。
3. 高风险命令必须二次确认。
4. 危险命令默认禁止。
5. 修改文件必须先展示 diff。
6. 读取敏感文件需要提示或禁止。
7. sudo 命令需要单独确认。
8. 远程下载脚本需要高风险提示。
9. 所有执行行为需要可审计。

## 9.2 高风险命令规则

高风险关键词：

```text
rm
chmod -R
chown -R
kill -9
systemctl stop
systemctl disable
docker system prune
kubectl delete
iptables
firewall-cmd
ufw
apt remove
yum remove
pip uninstall
```

危险关键词：

```text
rm -rf /
mkfs
dd if=
fdisk
parted
:(){ :|:& };:
> /dev/sda
curl xxx | bash
wget xxx -O- | sh
```

## 9.3 敏感信息脱敏

需要识别并脱敏：

- API Key。
- Token。
- Password。
- SSH 私钥。
- `.env` 文件内容。
- Kubernetes kubeconfig。
- 云厂商 AK/SK。
- 数据库连接串。

脱敏示例：

```text
OPENAI_API_KEY=sk-****************1234
PASSWORD=********
```

## 16. 主要风险与应对

### 风险一：命令执行安全风险

应对：

- 命令风险识别。
- 用户确认。
- 高风险二次确认。
- 危险命令拦截。
- 执行日志审计。

### 风险二：AI 生成错误命令

应对：

- 每步只生成一条命令。
- 展示原因和预期结果。
- 允许用户修改。
- 执行失败后自动回滚思路。

### 风险三：远端 Agent 安装失败

应对：

- 提供诊断工具。
- 支持手动安装命令。
- 支持无 Agent 降级模式。

### 风险四：用户不愿换终端

应对：

- 第一版提供内置终端。
- 第二版适配 Xshell/MobaXterm。
- 保留远端 `ai` 命令能力。

### 风险五：隐私和敏感信息

应对：

- 本地脱敏。
- 敏感文件默认不读取。
- 用户可配置数据保留策略。
- 企业版支持私有化。

## 18. 最终产品愿景

AI Shell Assistant 的长期愿景是成为：

> **面向普通开发者和 Linux 小白的智能命令行操作系统入口。**

用户不再需要记住大量 Linux 命令，也不需要独自面对复杂报错。用户只需要描述目标，AI 就能把目标拆解成安全、可解释、可确认执行的操作步骤，并持续根据执行结果推进任务。

最终形态不是简单命令生成器，而是：

```text
自然语言任务入口
+ 命令行执行 Agent
+ 报错分析器
+ 安全执行器
+ 项目运行向导
+ 运维排障助手
```

一句话总结：

**让 Linux 命令行从“靠经验敲命令”变成“自然语言驱动、AI 辅助、用户掌控的安全操作流程”。**
